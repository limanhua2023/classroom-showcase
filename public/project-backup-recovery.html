RECOVERY DRILL

标准恢复步骤

按这个顺序恢复，可以把“代码仓库、运行配置、云端对象存储、备份代理”四条链路重新连起来。

1. 取回代码 ZIP

优先使用本机 project_backup 中最近的 ZIP；如果电脑损坏，则从 R2 的 classshow-system-backups/codebase/... 取回同名 ZIP 和 manifest。

2. 恢复到干净目录

在新电脑或干净目录解压 ZIP，不直接覆盖未知环境。恢复后先检查 server.js、public/、scripts/、data/ 是否齐全。

3. 单独恢复关键配置

默认项目快照不会打包 secret 文件，所以需要手动补回 Render 环境变量、Supabase Secret key、Cloudflare R2 Access Key，以及本地两个备份代理的 .env 文件。

4. 重新部署并验收

执行 npm install 后重新部署 Render，检查 /api/health、教师后台、超级管理员页、R2 归档、Supabase 热层和本地备份代理状态是否都恢复健康。

CRITICAL CONFIG

关键配置单独恢复说明

这些内容默认不放进 ZIP，必须单独保管；项目代码恢复成功，不代表密钥和环境变量会自动恢复。

Render 生产环境变量

至少恢复：APP_SECRET、SUPER_ADMIN_PASSWORD、SUPABASE_URL、SUPABASE_ANON_KEY、SUPABASE_SERVICE_ROLE_KEY、归档/R2 相关变量、视频转码变量。

Supabase 高权限密钥

使用 sb_secret_... 作为后端高权限 key；不要把 sb_publishable_... 当成恢复用密钥。若怀疑泄露，应先旋转再回填。

Cloudflare R2 S3 凭证

恢复时需要：bucket 名、endpoint、Access Key ID、Secret Access Key。不要把通用 API token 文本误当成 S3 Access Key 使用。

本地备份代理配置

恢复本机后，重新检查 .env.local-backup.local 与 .env.project-backup.local，并重新安装计划任务，确保本地镜像和项目级快照会继续自动运行。
